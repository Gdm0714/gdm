# 동일 입력 리뷰 품질 실험 결과

이번 표본에서 Astra는 목표 결함을 모두 찾으면서 확인된 오탐을 적게 냈고,
추가 결함을 한 번 발견했다. 실제 구현 결과나 설계 품질의 향상을 입증한 실험은 아니다.

| 지표 | Terra medium | Astra medium |
|---|---:|---:|
| 실제 Pi 리뷰 호출 성공 | 16/16 | 16/16 |
| 목표 결함 발견 | 8/8 | 8/8 |
| 추가로 확인된 결함 지적 | 0 | 1 |
| 확인된 잘못된 지적 | 5 | 0 |
| 판정 미확정 지적 | 5 | 4 |
| 유효 시간 중앙값 | 17.6초 | 8.4초 |
| 16회 전체 API 정가 추정 | $0.2255 | $0.4105 |

목표 결함 4종은 scout effort 입력 거부, 시작 실패를 실행으로 세는 오류,
완료 검증에서 감사 증거를 덮어쓰는 오류, 동시 저장 시 임시 파일 충돌이다.
각 결함과 수정 대조를 같은 모델에 2회씩 입력했다. 같은 packet/system bytes를
사용한 도구 없는 Pi 리뷰어 직접 호출이며 진행 모델의 위임 결정은 개입하지 않는다.
실행 로그에서 요청한 모델과 Pi가 보고한 모델의 일치를 확인했다.

Terra의 오탐 5건 중 4건은 입력이 표준 import·ROOT·GdmError를 제공한다고
명시했는데도 발췌 코드에 import가 없다는 이유로 컴파일 불가를 지적한 것이다.
나머지 1건은 정규식의 `{12,}`를 `{12}`로 잘못 읽어, 실제로 탐지되는 문자열을
탐지하지 못한다고 주장했다. 후자는 모델이 제시한 반례를 실행해 반증했다.

Astra의 추가 발견은 문자열을 JSON으로 직렬화한 뒤 검사하면서 탭 문자가
이스케이프되어, 원래 Bearer 패턴이 탐지하는 입력을 놓치는 문제다. 같은 재현을
결함 버전과 수정 대조에 모두 적용해 확인했다. 4개의 원래 결함 분모에는 추가하지 않았다.
이 지적은 한 번만 나왔으므로 반복적인 탐지 능력으로 주장하지 않는다.

미확정 9건은 공백만 있는 문자열을 허용해야 하는지 불명확한 계약 1건과,
JSON 로더의 범위가 모호한 지적 8건이다. 로더가 숫자 값을 반환하는 현상은
재현됐지만, 입력이 해당 코드를 unchanged라고 부르면서 candidate addition에
넣어 리뷰 범위가 충돌한다. 이를 임의로 정답이나 오답으로 확정하지 않았다.
모든 미확정을 오답/정답으로 각각 처리한 지적 정확도 범위는 Terra 44.4–72.2%,
Astra 69.2–100%다. 이것은 통계적 신뢰구간이 아니라 판정 불확실성의 범위다.

8개 입력은 실제 GDM 소스에서 관련 부분을 추출해 재구성한 사례다. 독립적인
결함 가족은 4개이며, 전체 PR 32개를 평가한 결과가 아니다. 특히 import 관련
오탐은 이 발췌 입력 형식의 영향을 받으므로 실제 저장소 리뷰의 오탐률로
일반화할 수 없다. 판단자는 모델명을 제거한 결과를 판정한 루트 AI이며 독립된
사람 전문가가 아니다. 비용은 Pi가 보고한 API 정가 추정이고 OAuth 실제 청구액은 아니다.

실행 중 보조 함수 본문 추출 오류를 발견해, 영향을 받는 C01/C03의 첫 호출 전에
수정했다. 기존 8회는 입력 해시가 동일해 그대로 보존했다. 원본 실행과 수정된
manifest를 모두 남겼고 어떤 모델 응답도 다시 호출하지 않았다. 중단 과정이
포함된 R08 및 그 비교 짝 R07을 시간 중앙값에서 제외했다(모델당 15회).

기존 Terra 메인 / Astra 설계·리뷰 구성은 유지했다. 이번 결과는 Astra 리뷰를
사용할 제한적인 근거를 더하지만, 모든 변경에 필수로 쓰는 정책이나 최종 코드
품질 향상까지 검증하지 않는다. 다음 단계는 실제 PR 문맥을 그대로 준 비교와,
동일한 구현자가 리뷰를 반영했을 때 남는 결함·불필요한 수정·수정 시간을 측정하는 것이다.
