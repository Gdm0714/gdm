# 개선 전후 성능 측정 — 2026-10-29

부분 화면 갱신과 반복 성공 로그 전달량은 크게 줄었다. 전체 화면 갱신은 느려졌고, 원본 보존·전체 요청 검사·회귀 기록에는 추가 비용이 든다. 모든 항목이 빨라진 변경은 아니다.

## 측정 조건

- Apple M4, 메모리 16 GiB, macOS 26.5.1. 최적화 release 빌드.
- 항목별 예열 후 전후 실행 순서를 번갈아 9쌍 측정. 세 제품의 측정과 컴파일을 서로 겹치지 않았다.
- 총 594개 측정 프로세스. 사용자 앱은 유지했으며 OneDrive 업데이트 등의 배경 부하가 있었다. 완전히 유휴한 실험실 측정은 아니다.
- 실제 화면·키보드·마우스 조작, 앱 재시작, 설치본 교체, 실제 모델 호출 없이 합성 입력만 사용했다.
- 중앙값과 원시 표본을 보존했다. 9회 표본의 p95는 관측 통계이며 장기적인 꼬리 지연 추정치가 아니다.
- gdmux 파서·스냅샷과 gdm은 개선 전 소스를 복원했다. gid는 이전 미커밋 변경이 섞여 있어 관련 생산 코드의 처리 함수만 추출한 비교다. 전체 구버전 앱 비교로 해석하지 않는다.

## gdmux: 화면 데이터 처리

40행×120열, 패널당 20회 예열 후 120프레임. 파서 처리 + 스냅샷 생성 + JSON 직렬화 + 결과 해제까지 측정했다. 화면 데이터와 JSON은 모든 프레임에서 동일했다. 아래 시간은 패널 한 번 갱신당 평균 처리량을 각 실행에서 구한 뒤 취한 중앙값이다. UI·IPC·터미널 표시까지의 입력 지연이 아니다.

| 작업 | 패널 수 | 전 µs/갱신 | 후 µs/갱신 | 전후 쌍 기준 시간 감소 | 전 → 후 최대 RSS 중앙값 MiB |
|---|---:|---:|---:|---:|---:|
| 커서 이동 | 1 | 65.68 | 14.33 | 78.3% | 2.14 → 2.12 |
| 커서 이동 | 8 | 63.06 | 13.73 | 78.5% | 3.34 → 3.52 |
| 커서 이동 | 32 | 63.01 | 13.37 | 78.8% | 7.17 → 7.84 |
| 한 줄 갱신 | 1 | 66.47 | 16.06 | 75.7% | 2.14 → 2.19 |
| 한 줄 갱신 | 8 | 63.93 | 15.63 | 75.6% | 3.34 → 3.53 |
| 한 줄 갱신 | 32 | 64.24 | 15.28 | 76.2% | 7.19 → 7.89 |
| 출력 스크롤 | 1 | 61.65 | 13.56 | 77.8% | 2.62 → 2.84 |
| 출력 스크롤 | 8 | 60.36 | 13.12 | 78.3% | 7.84 → 8.27 |
| 출력 스크롤 | 32 | 62.20 | 12.93 | 79.3% | 25.31 → 26.70 |
| 전체 화면 갱신 | 1 | 80.60 | 89.57 | -11.7% | 2.94 → 2.98 |
| 전체 화면 갱신 | 8 | 80.66 | 86.44 | -7.8% | 4.16 → 4.42 |
| 전체 화면 갱신 | 32 | 79.84 | 87.65 | -9.7% | 7.97 → 8.78 |

음수 감소율은 더 느려졌다는 뜻이다. 전체 화면이 바뀌면 캐시 확인·갱신 비용이 추가된다. 최대 RSS는 격리된 벤치마크 프로세스 값이며 실제 gdmux 앱 전체 메모리가 아니다. wire 출력 크기는 전후 같으므로 네트워크 대역폭 절감은 없다.

## gid: 모델에 전달되는 도구 결과

기존 32 KiB/2,000줄 제한을 기준으로 비교했다. 원본 전체와 축약본을 비교해 절감률을 계산하지 않았다. 아래는 안내 문구와 파일 경로를 포함한 content의 UTF-8 바이트다. 청구 토큰 수나 전체 대화 비용이 아니다.

| 입력 사례 | 전 bytes | 후 bytes | 크기 감소 | 마지막 오류 보존 전 → 후 |
|---|---:|---:|---:|---|
| small | 57 | 57 | 0.0% | 해당 없음 → 해당 없음 |
| cargo_success_200 | 7,290 | 332 | 95.4% | 해당 없음 → 해당 없음 |
| cargo_success_5000 | 32,917 | 335 | 99.0% | 해당 없음 → 해당 없음 |
| cargo_failure_tail | 32,917 | 481 | 98.5% | 누락 → 보존 |
| unknown_verbose | 32,917 | 32,951 | -0.1% | 누락 → 보존 |
| unicode_tail | 32,917 | 32,951 | -0.1% | 누락 → 보존 |
| retention_overflow | 32,917 | 32,951 | -0.1% | 누락 → 보존 |

성공 테스트 로그는 크게 줄지만 일반 장문 로그는 거의 같은 크기다. 후자는 마지막 오류가 보존되는 이득이 있다. 8 MiB 초과 입력의 원본 전체가 보존되는 것은 아니며, 손실 표시와 앞·뒤 부분을 남긴다.

### 로컬 처리 비용

finish는 출력 보존 한도 처리, 실제 파일 쓰기와 fsync를 포함한다. 프로세스 생성·실제 셸 작업·모델 응답 시간은 제외한다. budget은 한도 계산 자체의 비용이다.

| 처리 | 입력 | 전 µs/회 | 후 µs/회 | 후 p95 배치 평균 µs/회 |
|---|---|---:|---:|---:|
| finish | small | 0.24 | 0.48 | 0.57 |
| finish | cargo_success_200 | 2.80 | 4910.62 | 5051.35 |
| finish | cargo_success_5000 | 4504.70 | 4829.66 | 4972.70 |
| finish | cargo_failure_tail | 4683.32 | 4667.07 | 6960.21 |
| finish | unknown_verbose | 4839.37 | 4611.97 | 4870.42 |
| finish | unicode_tail | 4628.26 | 4687.39 | 4964.55 |
| finish | retention_overflow | 8908.58 | 9390.27 | 10216.17 |
| budget | context_8k | 2.58 | 42.92 | 43.49 |
| budget | context_160k | 56.13 | 363.53 | 367.79 |
| budget | context_escaped_160k | 53.36 | 356.69 | 366.89 |
| budget | context_images | 0.37 | 28.14 | 29.74 |

200개 성공 테스트 사례는 이전에는 파일을 만들지 않았지만, 이제 생략된 내용을 다시 읽을 수 있도록 보존하여 약 5ms가 추가된다. 전체 요청 계산은 시스템 지침·도구·이미지 예약량·CLI 이스케이프 비용을 더 확인하므로 CPU 비용이 증가했다. 계산에 포함된 바이트가 늘어난 것은 실제 요청에 그만큼 새 데이터를 추가했다는 뜻이 아니다.

## gdm: CLI 처리

10개 합성 Work와 실패 기록 200건. status 출력과 retro의 기존 필드는 동일하다. retro에는 회귀 후보 200건이 추가된다.

| 명령 | 전 wall 중앙값 ms | 후 wall 중앙값 ms | 전 → 후 CPU 중앙값 ms | 전 → 후 wall p95 ms |
|---|---:|---:|---:|---:|
| status | 6.526 | 7.016 | 5.438 → 5.699 | 7.430 → 7.782 |
| retro | 7.293 | 7.834 | 5.963 → 6.721 | 8.292 → 8.661 |

status의 실행 범위는 거의 같으며 측정 범위가 겹친다. 이번 약 0.5ms 차이를 확정적인 코드 회귀로 단정하지 않는다. retro는 추가 조회·해시·출력을 수행한다.

새 회귀 replay는 단순 cmp 실행 3.547ms 대비 86.192ms였다. 고정 입력·출처 검사·프로세스 그룹·내구성 있는 결과 기록을 추가하므로 동등 기능의 전후 비교가 아니다.

## 해석과 남은 측정

- 스크롤·부분 갱신에서는 화면 처리 최적화의 이득이 확인됐다. 전체 화면 갱신 경로에는 추가 최적화 여지가 있다.
- 성공 로그 축약은 모델 입력을 줄인다. 전체 작업의 청구 비용·성공률·답변 품질 향상은 별도 실험이 필요하다.
- 모델 변경 인계 품질, 실제 압축 모델 호출 시간, 이벤트 정합성, 수신 큐가 체감 입력 지연에 미치는 효과는 이 성능 수치로 입증하지 않았다. 이전 회귀 검증과 성능 측정은 구분한다.
- 벤치마크용 파일만 추가했으며 제품 코드·설치본·실행 세션은 변경하지 않았다.
