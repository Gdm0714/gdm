# Pi 모델 배분 비교

[적용 결정과 64회 실측 결론](outcome-2026-09-08.md),
[상세 결과](results-2026-09-08.md)를 먼저 읽는다.

현재 역할 구성의 구현과 실제 Pi 비교를 함께 검증한다. 실행 입력·과제·모델·순서·시간 상한은
`active-run.json`이 가리키는 `manifest.json`에 실행 전에 고정한다. 원시 결과는 저장소 밖의
`~/projects/harness-bench-runs/`에 보존한다.

| arm | 메인 | 위임 |
|---|---|---|
| legacy | Sol xhigh | 이전 공통 자식 설정 Sol xhigh |
| terra | Terra high | 없음 |
| routed | Terra high | scout Luna medium, design/reviewer Astra medium; 어려운 설계·검토 high 허용 |
| astra | Astra low | 없음 |

모든 arm은 같은 새 Pi 실행 자산·gdm-go 지침·검증 게이트를 사용한다. legacy는 이전 모델
설정을 비교하는 대조군이며, 이전 실행기 버그나 이전 지침을 함께 되돌리지 않는다. Luna는
이번 비교에서 조사 작업자로 측정하며 독립 메인으로 평가하지 않는다.

8개 과제를 2회씩 반복해 총 64회 실행한다. 두 번째 반복은 과제별 arm 순서를 뒤집는다.
모델 실행은 순차적이며 한 번의 기록을 성공할 때까지 덮어쓰거나 재실행하지 않는다.
과제당 420초 상한이고 자식 호출은 180초 상한이다. 실패와 누락된 사용량도 기록한다.

1. t1: 내보내기 0 한도와 병동 전동 결함 수정 — 기존 fixture
2. t2: 백분위·CSV 기능 추가 — 기존 fixture
3. t3: 오류 행을 수집하는 안전 파서 — 기존 fixture
4. t4: tenant 권한 캐시 격리와 무효화
5. t5: 송금 원자성·멱등성·receipt 스냅샷
6. t6: 재시도 큐의 lease token·backoff·상태 전이
7. t7: 반개방 예약 구간과 최대 동시 사용량
8. t8: 무효화와 성공·실패가 교차하는 비동기 캐시

새 fixture 5개는 수정 전 숨긴 테스트 실패와 정답 구현 통과를 먼저 확인했다. 모델에는
과제별 소스와 요구만 제공하며, 숨긴 테스트는 실행이 끝난 후에 투입한다. 파일시스템 자체로
모델의 상위 디렉터리 읽기를 봉쇄한 실험은 아니므로 이 경계는 프롬프트 계약이다.

`run.py`는 Pi JSON의 assistant `message_end`만 합산해 스트리밍·종료 이벤트 중복을 피한다.
자식의 사용량도 포함한다. Pi가 표시하는 API 가격 추정은 구독 한도나 실제 청구액이 아니다.
main이 오류·timeout으로 종료하면 완전한 사용량 비교에서 제외하며 부분 사용량은 원시 기록에 남긴다.

```bash
cd cli && bun run build
cd ..
python3 bench/model-routing/run.py --prepare --execute
python3 bench/model-routing/analyze.py
python3 bench/model-routing/verify.py
```

`--prepare`는 새 실험을 만든다. 중단 후에는 기존 `active-run.json`을 보존하고 `--execute`만
사용한다. 실행 중이거나 결과 기록 전 중단된 디렉터리는 자동 재시도하지 않는다. 중단 원인을
기록하고 기존 로그를 먼저 평가해야 한다.

성공률은 실패를 포함한 모든 실행으로 계산한다. 시간·사용량은 같은 과제와 반복에서 둘 다
성공한 쌍을 따로 비교한다. 탐색적인 불확실성 구간은 과제 단위 bootstrap으로 계산한다.
8개의 작은 합성 과제 결과를 실제 대규모 프로젝트의 결함률로 일반화하지 않는다.

`verify.py`는 manifest와 파일 해시, 원시 이벤트에서 재계산한 수치, 요청·보고 모델, 독립적인
숨긴 테스트 재실행, 설치 파일과 기본 모델 설정을 검사한다. 완료 확인 과정에서 모델을 다시
호출하지 않는다. 실제 VM focus·memory 기능과 gdm-full 공식 검수는 이 비교 범위 밖이다.

비교 전 한 차례의 Sol 예비 실행은 `canary.json`에 별도 보존했다. 스트림 재시도 처리 검토를
마친 뒤 최종 실행 자산을 고정했으므로 그 예비 실행은 비교 수치에 합치지 않는다.

초기 비교 배치에서도 생성된 스킬에 `scout|reviewer`만 허용한다는 이전 문구가 남아 있는 것을
발견했다. 완료 10건과 중단 1건은 `superseded-batch.json`으로 보존했다. 설계 역할의 충돌을
수정하고 전체 회귀 검사·설치·실제 역할 호출 검증을 마친 뒤 새로운 배치를 고정한다.
초기 배치 결과는 최종 순위에 합치지 않는다. `pause` 파일을 실행 디렉터리에 만들면 진행 중
관측을 마친 경계에서 일시 중단하며, 파일을 지운 뒤 같은 배치를 재개할 수 있다.

최종 배치의 t4에서 원래 채점이 유효한 write-through 최적화를 오답으로 처리하는 것을
발견했다. 조회가 정확히 3회여야 한다는 단언 하나를 2회 또는 3회로 보정했다. 모델 입력과
동결된 원채점은 그대로 보존하며 모든 구성·반복에 동일하게 보정 채점을 추가한다.
`grader-correction.json`에 발견 시점·이유·해시, `adjudication.json`에 실행별 원채점과
보정 결과를 함께 기록한다. `analyze.py`와 `verify.py`는 이 보정도 재계산한다.
