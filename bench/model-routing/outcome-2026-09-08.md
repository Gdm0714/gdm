# Pi 모델 구성 적용과 실측 결론 — 2026-09-08

**Terra high를 일상 메인으로 유지한다. 적용한 역할 분담 구성은 기존 Sol xhigh보다
시간 약 48%, API 추정 비용 약 64%를 줄였다. 테스트 품질은 동률이었다.**
이번 이득은 메인 모델·추론 강도 변경을 지지한다. Luna/Astra 협업의 추가 이득은 확인하지 못했다.

## 64회 실제 Pi 비교

같은 gdm-go 지침과 실행기를 사용해 8개 합성 과제를 구성별로 2회씩 실행했다.
두 번째 반복은 과제별 모델 순서를 뒤집었다. 모델·추론 강도·위임 도구 유무를 합친 운영 구성 비교다.
시간은 실제 수정·테스트·gdm 완료 확인을 포함하며, 표의 시간과 비용은 실행별 중앙값이다.

| 구성 | 원채점 성공 | 보정 성공 | 시간 | API 추정 비용/회 |
|---|---:|---:|---:|---:|
| 기존 모델 설정: Sol xhigh | 14/16 | 16/16 | 243.4초 | $0.4128 |
| Terra high 단독 | 15/16 | 16/16 | 107.6초 | $0.1227 |
| 적용한 구성: Terra high + 역할 도구 | 15/16 | 16/16 | 118.6초 | $0.1506 |
| Astra low 단독 | 16/16 | 16/16 | 110.3초 | $0.4723 |

같은 과제·반복끼리 계산한 비율의 중앙값은 다음과 같다. 위 표의 중앙값을 나눈 비율과는 다르다.

- 기존 Sol → 적용 구성: 시간 **48.0% 감소**, API 추정 비용 **63.7% 감소**. 16쌍 모두 시간이 짧고 비용 추정이 낮았다.
- 기존 Sol → Terra 단독: 시간 **53.0% 감소**, API 추정 비용 **67.7% 감소**.
- Terra 단독 → 역할 도구 제공: 시간 **18.6% 증가**, API 추정 비용 **14.5% 증가**.
  시간 비율의 과제 단위 bootstrap 95% 구간은 0.975–1.256으로 변동이 크다.
- 적용 구성 → Astra low 단독: 시간 비율 0.890, API 추정 비용 비율 3.397.
  시간 비율 구간은 0.792–1.065다. 이번 표본으로 Astra의 일관된 속도 우위를 주장하지 않는다.

첫 Sol 실행에는 서비스 오류 후 자동 재시도가 있었다. 이를 제외해도 적용 구성의 시간 비율은
0.532로, 약 46.8%의 감소가 남았다. 주 비교에는 해당 실행을 그대로 포함했다.
API 추정 비용은 Pi가 보고한 카탈로그 가격 계산값이며 **구독 크레딧 차감액이나 실제 청구액은 아니다.**

## 모델 사용 결정

| 용도 | 적용한 기본값 | 운영 방식 |
|---|---|---|
| 일상 구현과 진행 | Terra high | 작은 수정은 직접 처리 |
| 범위가 명확한 조사 | Luna medium | 독립 조사에 이득이 있을 때 scout 호출 |
| 설계 | Astra medium | design 호출, 어려운 경우 high 선택 가능 |
| 중요한 코드 검토 | Astra medium | reviewer 호출, 어려운 경우 high 선택 가능 |
| gdm-full 독립 검수 | Astra medium | 구현 모델과 다른 실제 모델 조건 유지 |

비교에서는 legacy와 역할 분담 구성 모두 자식 모델 실행이 0회였다.
2026-09-09 로그 재확인에서 역할 분담 구성의 `t1-routed-2`가 Luna `scout` 위임을
1회 시도했으나 `thinking: medium` 때문에 실행 전에 거부된 사실을 확인했다.
노출된 도구 스키마는 모든 역할에 이 필드를 허용하지만 실행 검사는 scout의 명시적
thinking을 거부한다. 나머지 15회에는 위임 도구 호출 자체가 없었고, Astra 설계·검토
호출 시도도 없었다. 기존 분석은 자식 결과만 세어 거부된 시도를 놓쳤다.
따라서 이를 모두 모델의 자발적 위임 생략으로 해석해서는 안 된다.
따라서 역할 도구가 있는 구성의 시간·비용을 **Luna/Astra 협업 비용이나 협업 품질 향상으로 해석할 수 없다.**
도구 노출과 관련 지침, 모델의 실행 변동이 함께 반영된 관측이다. 일상적인 작은 작업에서
역할 분담을 강제하거나 새로운 자동 위임 단계를 더할 근거는 없다.

역할 배분 자체는 별도 실제 호출로 확인했다. Terra 진행자가 Luna medium 조사,
Astra medium 설계, Astra high 검토를 순서대로 호출했으며 요청 모델과 응답 모델이 일치했다.
자식 호출 시간은 각각 14.6초, 20.3초, 27.4초였고 소스는 변경되지 않았다.
이 검증은 역할 선택이 작동한다는 증거이며 비교 우위를 입증하는 실험은 아니다.

Astra 직접 구현도 선택지로 유지한다. 이번 Astra low는 모든 과제를 해결했고,
역할 도구가 있는 Terra보다 16쌍 중 11쌍에서 빨랐다. 큰 설계나 복잡한 구현에서 사용할
판단 근거는 [기존 공식 자료·경험담 조사](decision-2026-09-08.md)와 함께 본다.
Luna 단독 메인은 이번 비교에 포함하지 않았으므로 그 품질이나 우열은 결론 내리지 않는다.

## 채점 오류와 제외 기록

t4의 원래 숨긴 테스트는 저장소 조회가 정확히 3회여야 한다고 요구했다.
그러나 브리프는 올바른 갱신과 캐시 최적화를 요구한다. 캐시를 즉시 갱신하는 구현은
2회 조회로 같은 요구를 충족한다. 이 정상 구현을 오답 처리한 단언 한 곳을 2회 또는 3회로 보정했다.

모델 입력과 원본 채점·로그는 변경하지 않았다. 모든 구성과 반복의 t4 8건에 동일한 보정 채점을
추가했고 모델을 다시 호출하지 않았다. 원채점의 실패 4건이 모두 이 이유로 통과했다.
수정 전 결함 구현은 보정 테스트에서도 실패하며, 두 가지 정상 구현은 통과하는 것을 확인했다.

설계 역할을 허용하지 않는 이전 스킬 문구를 발견해 중단했던 초기 배치의 완료 10건과
중단 1건, 별도 예비 실행은 최종 64회에 합치지 않았다. 제외 이유와 원시 기록은 보존했다.

## 적용과 검증

gdm 0.11.0과 역할별 설정을 설치했다. 일반 Pi 기본 설정도 `openai-codex/gpt-5.6-terra`,
`high`로 변경했다. 기존 터미널의 `pi` 별칭은 `gdm-pi`를 가리키므로 **새 Pi 세션부터 적용된다.**
다른 Pi 설정은 보존했다. 메인·자식 모델 설정은 분리했고, 자식은 역할별 설정 → 기존 CHILD 설정 →
역할 기본값의 우선순위를 적용한다. 변경 전 설치본과 설정은 백업했다.

전체 회귀 검사 476개 통과·3개 건너뜀, 타입 검사·빌드·smoke를 확인했다.
최종 재검사 중 기존 Computer Use 테스트의 시간 의존성을 발견해 준비 신호 방식으로
고쳤다. 실패 기록과 수정 범위는 [회귀 검사 메모](final-regression-note.md)에 보존했다.
64개 실행의 로그 해시와 수정본 일치, 원래 테스트의 독립 재실행, 사용량 재계산,
채점 보정, 설치 파일과 실제 역할 호출도 검증했다. 최종 완료 게이트 기록은
[GDM Work](../../.gdm/pi-model-routing-20260908/work.md)에 남는다.

장시간 비교 중 별도 `harness-repository-separation` 작업이 Native·홈페이지·디자인 자산을
분리했다. 이 변경은 이번 모델 실험이 작성한 것이 아니다. 완료된 별도 작업의 검증 증거와
변경된 문서·파일 부재를 [보존 기록](concurrent-change.json)으로 고정하고, 완료 검사에서
그 상태가 유지되는지 확인한다. 해당 제품 파일을 복원하거나 추가로 변경하지 않았다.

실험은 작은 합성 과제 8종이며 3종은 이전 과제를 재사용했다. 실제 대규모 프로젝트의 품질,
memory·Computer Use를 포함한 전체 대화 환경, gdm-full 검수 품질은 이번 실측 범위에 포함하지 않았다.
