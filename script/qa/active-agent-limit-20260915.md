# 서브에이전트 실행 제한 수정

GDM native hook의 누적 32회 차단과 초기 16회·4회 확장 조건을 제거했다.
현재 pending/running 예약과 연결되지 않은 활성 관찰만 실행 제한 32개에 계산한다.
기존 런타임 동시 실행 4명 설정은 유지한다.

stopped, failed, expired 이력은 자리를 차지하지 않는다. 누적 횟수와 예약 기록은
감사 및 동일 호출 재전달 차단을 위해 보존한다. 취소 요청만으로 실행 종료를 가정하지 않는다.
연결된 관찰은 예약과 중복 계산하지 않으며, caller 연결은 복사본에서 먼저 계산하여
용량 부족으로 거부할 때 원본 연결 관계를 바꾸지 않는다.

## 검증

- 수정 전 동일 회귀 명령에서 33번째 호출 거부를 재현했다.
- 수정 후 종료·실패·만료를 섞은 96회 순차 호출과 다음 호출이 허용됐다.
- 활성 32개일 때 다음 호출 거부, 하나 종료 후 즉시 자리 재사용을 확인했다.
- 33개 프로세스의 동시 Pre 요청에서 32개 허용·1개 거부를 확인했다.
- 미연결 관찰 TTL, 연결 관찰 중복 제외, caller 연결 직전 경계값을 검증했다.
- 훅·정책·렌더러·동시 설정 91개와 설치·CLI 46개 테스트 및 타입 검사가 통과했다.
- 설치된 바이너리 검증은 `python3 script/qa/active-agent-limit-installed.py`로 재현한다.
  모델을 반복 호출하는 벤치마크가 아니라 훅 이벤트와 격리 원장을 사용하는 회귀 검사다.
- 설치 전 관찰한 실제 원장 39개의 파일 해시가 설치 후에도 동일했다.
  누적 458회 기록을 보존하면서 활성 실행은 0개로 구분해 표시했다.

GDM 검증 기록: `.gdm/active-agent-limit/`. 실제 설치본과 기존 원장 복사본의
검증 결과는 `out/c4.txt`에 기록한다. 검사는 원래 세션 원장을 수정하지 않는다.

## Astra 검수

`active_limit_design` 에이전트를 `gpt-6-astra`로 실제 호출하여 설계와 최종 코드를 검토했다.
설계 검토에서 caller 연결에 따른 중복 계산과 만료된 연결 관찰의 재계산 위험을 찾아 반영했다.
최종 검수 결과는 차단할 결함 없음이다. 검수자는 테스트를 별도로 재실행하지 않았다.

이는 새 spawn의 입장 제한이다. 늦은 lifecycle 이벤트로 예약이 다시 활성화될 때는
관측 수가 잠시 32를 넘을 수 있다. 이력을 버리거나 이미 실행 중인 작업을 강제로 종료하지 않는다.
부모별 childQuota와 Pi의 별도 위임 계약은 이번 세션 32회 수정 대상에 포함하지 않는다.

설치 전 백업: `~/.local/share/gdm/backups/active-agent-limit-20260915T020149Z/`.
