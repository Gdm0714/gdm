# gdm 역할·역량 배정 계약

> 저장소 정본. `install.sh`는 `_shared`를 설치하지 않으므로 각 스킬은 자기 역할 규칙을
> SKILL.md에 인라인하고 이 문서를 사람이 보는 정본으로 인용한다. 규칙을 바꾸면 관련
> 스킬의 인라인 규칙도 함께 고친다.

## 책임

현재 사용자와 대화하는 세션이 **진행자**다. 진행자는 사용자 문답, 저장소 조사, 작업 계약,
gdm 게이트, 최종 보고를 소유한다. 역할 실행을 다른 프로세스에 맡기더라도 이 책임은 넘기지 않는다.

역할은 계획·구현·리뷰·검수로 나누고 다음 기준으로 배정한다.

- 사용자와의 문답이나 저장소 맥락이 핵심이면 현재 세션이 직접 수행한다.
- 경량 구현은 현재 실행자가 직접 수행한다. 작은 단계를 매번 외부 프로세스에 넘기지 않는다.
- 독립적으로 경계를 나눌 수 있는 작업만 비대화형 CLI 실행으로 위임한다.
- 제품 파일을 쓰는 실제 구현 주체는 한 명으로 유지하고 그 모델을 작업 기록에 남긴다.
- 역할 이름이나 위임 보고보다 gdm의 check·증거·journal을 판정 정본으로 삼는다.

## 역할 배정

| 역할 | 스킬 | 소유자 | 필수 불변식 |
|---|---|---|---|
| 계획 | gdm-plan | 현재 세션 | 사용자 문답·코드 조사를 직접 하고 지속 계획·계약을 남긴다 |
| 경량 구현 | gdm-go | 현재 실행자 | gdm 증거가 통과해야만 완료한다 |
| 중량 구현 | gdm-full | 지정한 제품 작성자 1명 | 실제 구현 모델을 기록하고 독립 검수 전 전달하지 않는다 |
| 리뷰 | gdm-review | 읽기 전용 역할 실행 | 실제 diff·증거를 읽고 후보를 반증·중복 제거한다 |
| 검수 | auditor | 실제 구현 모델과 다른 모델 | 새 컨텍스트에서 직접 증거를 확인한다 |

## 검수 독립성

검수 모델은 실제 diff를 만든 구현 모델과 달라야 한다. 조율자나 스킬 이름이 아니라 실제
구현 주체를 기준으로 판단한다.

- 검수자는 현재 대화나 실행자의 결론 요약을 받지 않는다.
- 입력은 지속 brief, 작업 계약, 실제 diff, gdm 증거 경로다.
- 같은 모델만 사용할 수 있으면 독립 검수를 통과로 낮춰 기록하지 않고 차단 상태를 보고한다.
- 검수 반려는 check로 환원하고 재검증한다. 검수 문장만으로 pass를 만들지 않는다.

## 비대화형 역할 실행

분리 가능한 역할을 외부 CLI로 실행할 때는 해당 역할 스킬 전문과 필요한 파일·증거 경로만
전달한다. 사용자의 비밀, 전체 대화, 불필요한 저장소 원문은 넘기지 않는다. 결과를 받은 뒤
진행자가 실제 파일과 gdm 게이트로 다시 판정한다.

실행 도구가 없거나 실패하면 원인을 기록하고 현재 세션이 안전하게 소유할 수 있는 역할만
직접 이어간다. 독립 검수는 같은 모델로 대체하지 않는다.
