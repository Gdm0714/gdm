# gdm native design system

- Reference: an aircraft operations board whose right-side maintenance ledger proves whether a task may close.
- Direction: Claude Design Direction A, with Direction B's signed-evidence grammar in the Proof Rail.
- Tone: quiet, dense, operational, and legible through a full workday.
- Theme: dark-only for the first native shell because terminal and evidence panes must share one luminance range.
- Signature: the Proof Rail is a top-to-bottom argument from contract to delivery, never a dashboard card stack.
- Typography: native macOS sans for UI and native monospaced type for commands, hashes, evidence, and shortcuts.
- Color: neutral surfaces establish panes; green, blue, amber, and red appear only as state signals.
- Structure: pane boundaries and alignment carry hierarchy; overlays are the only floating surfaces.
- Do pair every status color with a glyph and a word.
- Do keep agent commentary in the terminal and deterministic records in the Proof Rail.
- Do expose every delivery blocker even when the rail is collapsed.
- Do use motion only to hand off state between existing surfaces; settled states stay still.
- Do honor Reduce Motion with zero-duration, single-commit state changes.
- Do keep official agent marks unmodified and visually separate from liveness signals.
- Do keep current and unfinished tasks visible while proven history stays available behind one disclosure.
- Do omit zero activity counters and persistent idle chrome without removing state glyphs or words.
- Don't use gradients, glass, decorative shapes, glow, generic chat bubbles, or equal floating cards.
- Don't use green for agent liveness; green belongs to proven GDM evidence.
- Don't enable completion from agent claims or view-local state.
- Don't shrink terminal or evidence text to make layout fit.
- Canonical tokens: `native/Sources/GDMNative/Resources/design-tokens.css`.
- Native mapping: `native/Sources/GDMNative/DesignTokens.swift` loads those bundled CSS tokens.
